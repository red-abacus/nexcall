# CRM API code and data model review

Recorded at `2026-11-05T17:46:19Z` UTC.

The review compares the API working tree with `master` at `58ffedf`, including the untracked CRM source and migrations. The model comparison uses the attached dbdiagram image `Pasted Image 1.jpg` and treats it as a proposed logical model. The findings and possible changes below are for review.

## API review against master

The CRM implementation uses the existing customer transaction manager and module facades, Spring request validation, `QueryResult` paging, and OpenCSV. The focused `JdbcClient` queries support tenant-scoped projections and ordered MySQL locks.

### Simplification candidates

- Use a tenant-scoped existence check for history and attachment reads, and an ID-only lock for writes that currently hydrate the contact and phones. A shared latest-attempt query can support bulk removal and script refresh, which currently reads the last element of an unordered association. [CRM history](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/crm/CrmContactHistory.java#L26), [Removal guard](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/services/CallTaskService.java#L162), [Script refresh](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/services/ScriptService.java#L145)
- Configure affected ModelMapper mappings at initialization, use the after-commit listener pattern for incoming notifications, and rely on JPA dirty checking for managed task updates. Disposition history uses durable outbox delivery. [Mapping guidelines](../../apps/api/docs/guidelines/dto-validation-mapping.md#mapping-and-entities), [Incoming-call notification](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/services/CallDetailsService.java#L908)
- Express create-only requirements in create DTOs, preserve PATCH field presence, and return tenant-aware `Location` headers on 201 responses. The raw JSON in `CrmContactRules` preserves old receipt fingerprints. A single typed model and fingerprint are viable if there are no stored receipts to support. [CRM controller](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/crm/CrmController.java#L41), [Rule binding](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/crm/CrmContactRules.java#L14)

The prior API run passed 204 tests, including nine on MySQL 8.4. The chart uses MySQL 8.0, and CI requires a database URL to execute those integration tests. [Verification handoff](../decisions/2026-11-05-crm-backend.md#crm-022-verification), [Chart database image](../../apps/api/deploy/helm/nexcall-api/values.yaml#L46), [CI test step](../../.github/workflows/deploy-api-gke-prod.yml#L45)

## Comparison with the proposed data model

The working tree implements the seven core entities and their main relationships. The physical schema differs on task scheduling and lineage, separate call rating, tenant business data, CRM auditing, and some keys and null constraints.

| Diagram entity | Current API model | Differences |
| --- | --- | --- |
| `Tenant` | `Customer` and `customer` are the tenant. `customer_id` is the tenant reference. | The tenant lacks `entityName`, `businessId`, `tradeRegistryId`, `bankAccount`, `bankName`, and `websiteUrl`. `CustomerStatus` has `ACTIVE` and `SUSPENDED`. The legacy database allows null status and deletion flags where the diagram marks them required. [Customer entity](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/entities/Customer.java#L17), [Customer DDL](../../apps/api/src/main/resources/db/changelog/000-customers-baseline.sql#L3) |
| `Campaign` | Campaign ownership, dates, name, Twilio number, photo, status, and type are present. | `campaign_type` defaults to `DEBT_RECOVERY` and is immutable through the API. The database stores campaign status as an enum and allows null `customer_id` and `is_deleted`, which the diagram marks required. [Campaign DDL](../../apps/api/src/main/resources/db/changelog/000-customers-baseline.sql#L28), [Campaign type migration](../../apps/api/src/main/resources/db/changelog/002-campaign.xml#L6) |
| `CrmAccount` | Tenant-owned `crm_account` with the diagram's business fields. | Uses `archived_at` instead of a deletion flag and has no row-level `createdDate` or `updatedDate`. Several optional strings use non-null columns with empty values. Description is `VARCHAR(2000)`. Country and classifier/code pairs have FKs, and an active tax key enforces tenant-scoped uniqueness. [CRM account DDL](../../apps/api/src/main/resources/db/changelog/001-crm.sql#L25) |
| `CrmContact` | Tenant-owned `crm_contact` with an optional account. The account FK includes the tenant, so the database prevents cross-tenant account links. | Uses `archived_at` and lacks row-level creation and update timestamps. Email and position are non-null columns that can be empty. Adds `lead_status` and `reason` for lead qualification. [CRM contact DDL](../../apps/api/src/main/resources/db/changelog/001-crm.sql#L50) |
| `CrmContactPhone` | Separate ordered rows for each contact. | Uses `(contact_id, slot)` as the primary key instead of a standalone ID. The API replaces the ordered list, caps slots at three, normalizes phones to E.164, and prevents a duplicate number on the same contact. [Phone DDL](../../apps/api/src/main/resources/db/changelog/001-crm.sql#L72), [Phone writes](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/crm/CrmContactRepository.java#L213) |
| `CallTask` | A campaign task with an optional `crm_contact_id` FK, copied contact fields, and the legacy debt-recovery fields. | `previousTaskId` and `scheduledAt` are absent. The API also stores account ID and name, position, source and lead-status snapshots. The database allows nullable campaign, status and deletion fields, and limits each campaign/contact pair to one non-deleted task, including completed tasks. [Task DDL](../../apps/api/src/main/resources/db/changelog/000-customers-baseline.sql#L71), [CRM task migration](../../apps/api/src/main/resources/db/changelog/002-campaign.xml#L21) |
| `CallDetails` | Call attempts reference tasks. The existing `CallStatus` enum carries the disposition. The diagram shows an enum named `CallOutcome` without its values. | No separate `callRating` is stored on the attempt. The reporting view called `call_rating` projects `call_status`. The task FK is nullable in the legacy schema. The API adds an attempt key, account-at-start snapshot, and operator disposition timestamp. Provider status, duration, and recordings live in `twilio_details`. [Attempt DDL](../../apps/api/src/main/resources/db/changelog/000-customers-baseline.sql#L148), [Attempt migration](../../apps/api/src/main/resources/db/changelog/003-history.sql#L1), [Rating view](../../apps/api/src/main/resources/reporting/scripts/call-rating-view.sql#L1) |

The API retries a call by requeuing the same task and recording a new attempt. If `previousTaskId` is intended to chain distinct follow-up tasks, a scheduling workflow must decide which task remains eligible and how a successor can coexist with its predecessor under the current uniqueness rule. The existing worker schedules maintain queues and campaigns. A per-task due time is a separate behavior. [Disposition transitions](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/services/CallDetailsService.java#L536), [Queue selection](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/services/CallTaskService.java#L234)

The legacy audit columns use MySQL `DATETIME(6)`, while the diagram labels them `timestamp`. A contact response also derives `lastContactAt` from non-note history. That value tracks outreach rather than edits to the contact row. [Legacy task DDL](../../apps/api/src/main/resources/db/changelog/000-customers-baseline.sql#L71), [Contact read projection](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/crm/CrmContactRepository.java#L26)

The task-to-contact link is tenant-scoped by the import service. Its database FK checks only the contact ID, while the contact-to-account FK also checks the tenant. The diagram leaves those cross-tenant integrity rules unspecified. [Import service](../../apps/api/src/main/java/com/nexcall/monolith/modules/customers/services/CampaignTaskOperations.java#L161), [Task FK](../../apps/api/src/main/resources/db/changelog/002-campaign.xml#L32)

The image also leaves out catalog tables, CRM update history, attachments and cleanup, the disposition outbox, CSV previews, and request receipts. These support the implemented web and calling flows beyond the seven core entities. [CRM catalog and records](../../apps/api/src/main/resources/db/changelog/001-crm.sql#L1), [History and outbox](../../apps/api/src/main/resources/db/changelog/003-history.sql#L7), [Campaign receipts and previews](../../apps/api/src/main/resources/db/changelog/002-campaign.xml#L37)
